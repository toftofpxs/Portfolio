Contexte détaillé

Objectif du dashboard

En première année de BTS SIO, j'ai participé à la création d'un dashboard de supervision système. L'objectif principal était de surveiller l'état du système d'information en temps réel, d'identifier les anomalies et de faciliter la prise de décision des équipes d'exploitation.

Résultats obtenus

Apports concrets

Le dashboard a été intégré avec succès dans l'outil interne de monitoring et permet à l'équipe d'exploitation de suivre les métriques critiques du SI. Les alertes sont correctement remontées et les données sont présentées de manière accessible et lisible.

Architecture du système

Le dashboard collecte les métriques système, les stocke en SQL et génère des alertes en cas d'anomalie.

Flux de données

Les données circulent des serveurs vers le dashboard via des requêtes SQL et des appels planifiés.

Extrait de code 01

Collecte de métriques

Le collecteur interroge les serveurs pour récupérer les états en temps réel.

public List<SystemMetric> collectMetrics() {
  List<SystemMetric> metrics = new ArrayList<>();
  for (Server server : servers) {
    SystemMetric m = fetchMetric(server);
    metrics.add(m);
  }
  return metrics;
}

Extrait de code 02

Enregistrement en base

Les métriques sont stockées en SQL pour garder un historique et créer des alertes.

public void storeMetric(SystemMetric metric) {
  String sql = "INSERT INTO metrics (serverId, cpu, memory, timestamp) VALUES (?, ?, ?, ?)";
  preparedStatement.setInt(1, metric.getServerId());
  preparedStatement.setDouble(2, metric.getCpuUsage());
  preparedStatement.executeUpdate();
}

Extrait de code 03

Génération d'alertes

Si une métrique dépasse le seuil critique, une alerte est générée et affichée.

if (metric.getCpuUsage() > CRITICAL_THRESHOLD) {
  Alert alert = new Alert("Cpu critique sur " + serverId);
  alertService.send(alert);
}

API mobile

REST Authentification Mobile

Contexte détaillé

Objectif du projet

L'API a été pensée pour alimenter une application mobile de gestion d'événements. Il fallait exposer des routes claires pour l'authentification, la consultation des événements, les inscriptions et la synchronisation d'informations côté application.

Contraintes

Points d'attention

Le projet devait proposer une structure de réponses cohérente, limiter les données exposées au strict nécessaire et rester simple à consommer depuis une interface mobile. La stabilité des contrats d'API était un enjeu central.

Diagramme de classes

Le modèle relie l'utilisateur, l'événement et l'inscription en gardant un contrat d'API simple.

Architecture MVC

L'application mobile consomme des contrôleurs REST qui orchestrent les règles métier et l'accès aux données.

Extrait de code 01

Route d'authentification

Cette route centralise l'identification et renvoie un jeton pour sécuriser les appels suivants.

router.post("/login", async (request, response) => {
  const user = await authService.login(request.body);

  response.json({
    token: user.token,
    profile: user.profile
  });
});

Extrait de code 02

Sérialisation de réponse

La réponse ne renvoie que les champs utiles au mobile pour limiter le volume et protéger les données sensibles.

function toEventDto(event) {
  return {
    id: event.id,
    title: event.title,
    date: event.date,
    slotsLeft: event.capacity - event.registrationsCount
  };
}

Extrait de code 03

Protection des routes

Le middleware contrôle la présence du jeton avant d'autoriser une inscription à un événement.

export function requireAuth(request, response, next) {
  const token = request.headers.authorization;

  if (!token) {
    return response.status(401).json({ message: "Accès refusé" });
  }

  next();
}

Résultats et bilan

Bilan du projet

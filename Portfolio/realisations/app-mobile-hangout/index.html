App mobile Hangout

React NativeExpoAPI RESTMobile

Contexte detaille

Objectif de l'application

La version mobile du projet Hangout permet aux utilisateurs de consulter des evenements, s'inscrire rapidement et suivre leur activite depuis un smartphone. Le projet devait conserver la logique metier du web tout en proposant une ergonomie tactile adaptee.

Resultats obtenus

Valeur apportee

L'application livre un parcours court et lisible avec authentification, tableau de bord et fiches d'evenements. Les ecrans sont optimises pour l'usage mobile et consomment les routes backend existantes via Axios.

Diagramme de classes

L'app mobile combine un store de session, des ecrans fonctionnels et un client API partage.

Architecture MVC

Les ecrans React Native deleguent les actions a des services qui consomment l'API backend.

Extrait de code 01

Connexion utilisateur

Le token recu a la connexion est stocke pour authentifier les appels suivants.

const response = await axios.post("/login", credentials);
await SecureStore.setItemAsync("token", response.data.token);
setSession(response.data.profile);

Extrait de code 02

Recuperation des evenements

Le hook recharge la liste en conservant un etat de chargement visible.

const loadEvents = async () => {
  setLoading(true);
  const { data } = await api.get("/events");
  setEvents(data);
  setLoading(false);
};

Extrait de code 03

Inscription a un evenement

Le bouton met a jour l'interface apres confirmation de l'API.

await api.post(`/events/${eventId}/register`);
setEvents((prev) => prev.map((item) =>
  item.id === eventId ? { ...item, isRegistered: true } : item
));

Resultats et bilan

Bilan du projet mobile

Cette realisation m'a appris a adapter une logique web au mobile sans perdre la coherence metier. J'ai renforce mes competences sur React Native, la gestion de session et l'optimisation des ecrans pour une lecture rapide.

Sprints du projet

Organisation Kanban (solo)

Sprint 1: initialisation de l'app Expo, navigation mobile et creation des ecrans principaux (connexion, accueil, details evenement).

Sprint 2: integration des appels API (authentification, consultation et inscription aux evenements) avec gestion des sessions.

Sprint 3: optimisation de l'interface mobile (ergonomie, performances), tests sur appareil mobile (Expo Go) et corrections finales.

Conformite RGPD

Articles appliques

Art. 5 §1 c) : principe de minimisation des donnees — l'application mobile ne collecte et ne transmet que les informations strictement necessaires (email, session token), sans acces aux contacts, localisation ou autre donnee hors perimetre.

Art. 32 §1 b) : securite du traitement assuree par le stockage du token d'authentification dans le SecureStore natif d'Expo (chiffre par l'OS), et par le recours exclusif a HTTPS pour tous les appels API.

Art. 13 §2 a) : la duree de conservation des donnees de session est communiquee lors du premier lancement de l'application, conformement a l'obligation d'information au moment de la collecte.

Art. 20 §1 : droit a la portabilite pris en compte — les donnees de l'utilisateur (profil, inscriptions) sont disponibles via l'API dans un format structure (JSON) permettant une exportation a la demande.

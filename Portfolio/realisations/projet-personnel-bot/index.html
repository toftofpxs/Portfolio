Projet personnel bot

Automatisation Commandes Journalisation

Contexte détaillé

Objectif du projet

Ce projet personnel avait pour but d'explorer la conception d'un bot capable de déclencher des commandes utiles, d'interroger des services externes et de conserver un historique des actions exécutées. L'idée était de pratiquer l'automatisation dans un cadre concret.

Périmètre

Cas d'usage ciblés

Le bot doit répondre à des commandes simples, formater les réponses de manière lisible et éviter les actions silencieuses. La priorité a été donnée à la traçabilité, à la robustesse et à la séparation entre commandes, services et logs.

Diagramme de classes

Les commandes déclenchent des exécutions qui sont ensuite journalisées pour garder une trace exploitable.

Architecture MVC

L'interface de commande délègue l'action au contrôleur, qui appelle les services et journalise le résultat.

Extrait de code 01

Registre de commandes

Le registre associe un nom de commande à une fonction dédiée pour garder un point d'entrée lisible.

const commands = {
  ping: handlePing,
  summary: handleSummary,
  help: handleHelp
};

Extrait de code 02

Journalisation

Chaque exécution est loggée pour garder un historique utile au débogage et au suivi du bot.

logger.info({
  command: input.name,
  user: input.userId,
  status: "started"
});

Extrait de code 03

Réponse sécurisée

Le bot renvoie un message explicite en cas d'échec pour éviter une expérience silencieuse côté utilisateur.

try {
  return await commands[input.name](input);
} catch (error) {
  return { message: "Commande indisponible pour le moment." };
}

Résultats et bilan

Bilan du projet

Ce projet personnel m'a servi de terrain d'expérimentation pour l'automatisation, la structuration de commandes et la robustesse des retours utilisateurs. Il m'a permis de mieux penser la séparation entre orchestration, services et logs.

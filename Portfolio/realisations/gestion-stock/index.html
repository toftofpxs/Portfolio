Gestion de stock

Contexte métier MVC Base de données

Contexte détaillé

Objectif du projet

Ce projet répond au besoin d'une petite structure souhaitant suivre ses articles, ses entrées et ses sorties sans passer par des feuilles de calcul dispersées. L'application devait centraliser l'inventaire, fiabiliser les quantités disponibles et signaler les ruptures avant qu'elles ne bloquent l'activité.

Résultats attendus

Ce que la solution apporte

La solution met à disposition un tableau de bord simple, une fiche article structurée, un historique des mouvements et des alertes sur les seuils critiques. L'accent a été mis sur la lisibilité, la cohérence des données et la rapidité de saisie.

Diagramme de classes

Les classes principales structurent l'article, les mouvements de stock et la traçabilité utilisateur.

Architecture MVC

La vue enregistre l'action, le contrôleur applique la règle métier et le modèle persiste les mouvements.

Extrait de code 01

Validation d'un mouvement

Ce contrôle évite qu'une sortie fasse passer le stock en valeur négative.

function validateMovement(article, quantity, type) {
  // Empêche les sorties impossibles avant l'écriture en base.
  if (type === "OUT" && article.stock < quantity) {
    throw new Error("Stock insuffisant");
  }

  return true;
}

Extrait de code 02

Mise à jour transactionnelle

La quantité est ajustée dans la même opération que l'enregistrement du mouvement pour conserver la cohérence.

await db.transaction(async (trx) => {
  await trx("movements").insert(payload);

  await trx("articles")
    .where({ id: payload.articleId })
    .update({ stock: nextStock });
});

Extrait de code 03

Alerte de seuil

Une alerte visuelle est déclenchée dès que le stock disponible passe sous le seuil paramétré.

const isCritical = article.stock <= article.alertThreshold;

return {
  ...article,
  badge: isCritical ? "Alerte stock" : "Stock stable"
};

Résultats et bilan

Bilan du projet

Le projet a montré l'importance de la cohérence entre règles métier et interface utilisateur. J'ai consolidé mes acquis sur la modélisation, la validation côté service et la clarté d'un flux métier orienté inventaire.

Sprints du projet

Organisation Scrum Agile

Sprint 1: cadrage du besoin, decoupage des user stories, priorisation du backlog et definition des criteres d'acceptation.

Sprint 2: developpement des fonctionnalites principales, points quotidiens (daily), integration continue et corrections des blocages.

Sprint 3: tests, stabilisation, revue de sprint avec demonstration, puis retrospective et plan d'amelioration pour la suite.

Backend

Node.js Express MySQL JWT

Contexte detaille

Objectif du backend

Le backend devait centraliser la gestion des comptes, des evenements et des inscriptions avec une API REST fiable. L'objectif etait de garantir des echanges clairs avec le frontend, un controle d'acces robuste et des regles metier simples a maintenir.

Resultats obtenus

Ce qui a ete livre

L'API expose des routes securisees, un schema de donnees coherent et des validations sur les operations sensibles. Le projet a permis de stabiliser les flux d'inscription et de rendre les erreurs plus lisibles pour l'interface cliente.

Diagramme de classes

Le modele relationnel relie utilisateurs, evenements et inscriptions avec un contrat API stable.

Architecture MVC

Le backend separe clairement les routes HTTP, les regles metier et l'acces aux donnees.

Extrait de code 01

Route d'authentification

La route de connexion valide l'utilisateur puis renvoie un token JWT pour les appels proteges.

router.post("/login", async (request, response) => {
  const user = await authService.login(request.body);

  response.json({
    token: user.token,
    profile: user.profile
  });
});

Extrait de code 02

Controle de capacite

Cette regle metier empeche les inscriptions quand la capacite maximale est atteinte.

if (event.registrationsCount >= event.capacity) {
  return response.status(409).json({
    message: "Evenement complet"
  });
}

Extrait de code 03

Middleware de protection

Le middleware verifie le token avant d'autoriser l'acces aux routes privees.

export function requireAuth(request, response, next) {
  const token = request.headers.authorization;

  if (!token) {
    return response.status(401).json({ message: "Acces refuse" });
  }

  next();
}

Resultats et bilan

Bilan du projet backend

Ce projet m'a permis de renforcer ma pratique d'Express, de la securisation JWT et du design d'API REST. J'ai egalement progresse sur la gestion des erreurs, la coherence des reponses JSON et le decoupage controleur/service.

Methode de travail

Organisation Kanban (solo)

Sprint 1: configuration du socle backend (Express, connexion base de donnees, modele utilisateur et authentification JWT).

Sprint 2: developpement des routes metier (CRUD evenements/inscriptions), validations des donnees et gestion des erreurs metier.

Sprint 3: securisation des endpoints (middlewares, droits d'acces), tests API Postman et stabilisation des reponses JSON.

Conformite RGPD

Articles appliques

Art. 6 §1 b) : le traitement des donnees personnelles (email, mot de passe hache) est licite car necessaire a l'execution du contrat de service (creation de compte, authentification).

Art. 25 : protection des donnees des la conception — les mots de passe sont haches via bcrypt, aucune donnee superflue n'est stockee en base (privacy by design et by default).

Art. 32 §1 b) : securite du traitement garantie par la signature des tokens JWT, leur expiration courte, et le transport exclusivement via HTTPS pour eviter l'interception.

Art. 17 §1 : droit a l'effacement mis en oeuvre via un endpoint dedie permettant a l'utilisateur de supprimer son compte et l'ensemble de ses donnees associees.
